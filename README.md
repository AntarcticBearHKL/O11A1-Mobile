# O11A1 移动端视频测试

![android-debug](https://github.com/AntarcticBearHKL/O11A1-Mobile/actions/workflows/android-debug.yml/badge.svg)
![ios-unsigned](https://github.com/AntarcticBearHKL/O11A1-Mobile/actions/workflows/ios-unsigned.yml/badge.svg)

仓库里有两套 V2 客户端：

- `expo-ui/`：iOS V2 客户端。Expo 壳 + 全屏 WKWebView + 本地回环 Bilibili 桥（`modules/o11a1-bridge`）；UI 仍然是 `web-prototype/`，播放走 HTML5 `<video>` + 本地 Range 代理。
- 根目录：Android V2 应用（`com.o11a1.videotest`）。全屏 WebView 承载 V2 设计 + 原生 Bilibili 桥 + 本地视频代理；播放完全交给系统 WebView 媒体层硬解。

## 只调 UI：Expo Go 模式

完整的 O11A1 app **不能直接**用 Expo Go 跑，因为 `expo-ui` 依赖自定义原生模块 `O11A1Bridge`（本地 HTTP 服务、Cookie、B 站接口、原生 WebView 宿主）。Expo Go 里没有这个模块，所以原来的行为是直接显示“原生模块未加载”。

现在 `App.tsx` 增加了 UI MOCK 回退：

- 在 Expo Go 中启动时检测不到 `O11A1Bridge`，会自动把 `web-prototype/` 的 `index.html / styles.css / app.js / native.js` 内联进一个 WebView。
- 注入 `window.O11A1Native` 的 mock 实现：热门/搜索/排行/番剧/直播/收藏/历史/关注/动态/消息/评论/楼中楼/会员任务都有假数据。
- 登录 gate、官方网页登录按钮、侧边栏、播放器设置抽屉、画质/弹幕设置/循环模式/评论/播放列表/主题/外观滑杆/键盘映射等 UI 都可以点。
- 视频播放、真实账号、AI、截图、复制链接会显示“UI 调试模式…”的内联提示，不会伪造成功。
- 左上角会显示 `UI MOCK · 无视频 / 无账号` 标识。

启动：

```bash
cd expo-ui
npm run dev
```

`npm run dev` 会同时启动 Expo 和 `web-prototype` 文件监听：改 `web-prototype/app.js / native.js / styles.css / index.html` 后自动重生成 `src/webapp.generated.ts`，Expo Go 会重新加载 WebView；改 `App.tsx` 则由 Metro Fast Refresh 处理。

快速在 Android 模拟器上自动打开 Expo Go：

```bash
npm run dev:android
```

iOS Simulator（macOS）：

```bash
npm run dev:ios
```

也可以分别启动：

```bash
npx expo start --lan
# 另一个终端
npm run watch:web
```

用 Expo Go 扫 Metro 的二维码，或在 Expo Go 里打开同一局域网地址。局域网不通时用：

```bash
npx expo start --tunnel
```

如果只想在电脑上快速看 UI，直接起一个静态服务器打开 `web-prototype/` 也可以；Expo Go 模式的好处是能在手机上测试触摸手势和横屏设置抽屉。

## iOS V2 实装（当前 IPA）

- **架构**：`expo-ui` 启动 `O11A1Bridge` 原生模块，在 `127.0.0.1` 随机端口起一个本地 HTTP 服务，把打包进 JS 的 `index.html / app.js / native.js / styles.css` 原样提供给 WKWebView。
- **同步桥**：注入 `window.O11A1Native`，通过同步 XHR 调本地 `/api/*`，与 Android 的 `WebAppBridge` API 完全一致，包括 UP 主空间 `space`（先请求旧版空间接口，失败时再用 WBI 签名请求新版接口，并补全 UP 名字、头像和粉丝数）；`native.js` 不需要分叉。
- **真实数据**：Swift `O11A1BiliClient` 直接请求 B 站热门、搜索、分页 cid、playurl、评论、弹幕、导航登录态、账户资料、收藏夹、历史、关注动态、动态、消息、排行榜、番剧/影视索引、番剧选集、直播推荐与直播地址、分区、视频详情；Cookie 持久化到 UserDefaults。
- **真实登录**：应用内打开 B 站官方登录页（手机号 / 密码 / 扫码等方式由官方页面提供）；登录成功后读取 WebKit Cookie 并保存 `SESSDATA` 等 Cookie；退出登录同时清理原生 Cookie 与 WKWebView Cookie，下次打开官方页保持未登录。
- **真实播放**：progressive MP4 优先 720P，失败回退 480P / 360P；本地 `/media` 代理补 Referer/UA、转发 Range，按 1MB 分块返回 206；主 CDN 失败自动试备用 CDN；番剧通过 `pgc/player/web/playurl` 播放并一次加入整季选集；直播使用原生 HLS。1080P 及以下默认走 progressive；DASH 仅在用户选择 720P 以上画质时启用，避免默认播放进入 MSE 长时间缓冲和 seek。
- **播放器**：与 Android 共用同一套 V2 播放器 UI、三区手势、评论、弹幕、播放列表、刷新和登录 gate；视频信息/性能面板、截图、复制链接、收藏/投币/关注/弹幕发送会调用真实接口（未登录时内联提示）；外接键盘映射、深色主题、全屏评论楼中楼/三段窗口无限列表、会员任务、AI 养鱼全部共用 web 实现。
- **构建**：GitHub Actions `ios-unsigned`（macOS）每次 push 生成未签名 IPA + 模拟器 zip；成功后发布到 Releases。
- **下载**：
  - IPA：`https://github.com/AntarcticBearHKL/O11A1-Mobile/releases/download/ios-unsigned/o11a1-ios-unsigned.ipa`
  - 模拟器包：`https://github.com/AntarcticBearHKL/O11A1-Mobile/releases/download/ios-unsigned/o11a1-ios-simulator.zip`
  - Android APK：`https://github.com/AntarcticBearHKL/O11A1-Mobile/releases/download/android-debug/app-debug.apk`
- **安装**：未签名 IPA 需要自己签名（Sideloadly / AltStore / eSign / 自有开发者证书）；模拟器 zip 解压后用 `xcrun simctl install booted O11A1.app`，需要 macOS。
- **CI 验证**：`ios-unsigned` 在 macOS runner 上启动 iOS Simulator，已实际跑通登录 gate → 真实推荐流 → 首个视频 720P 播放 + 弹幕。Release 里的 `ios-simulator.png` 是登录 gate，`ios-simulator-player.png` 是真实播放画面。真机仍需你自己签名后测试。
- **系统亮度 / 音量**：播放器不再监听左右竖滑，也不提供应用内亮度或音量滑杆；亮度和音量完全交给系统控制。进入、退出播放器都不会修改或恢复系统亮度，也不会修改 `<video>` 元素音量；外接键盘的音量快捷键也已移除。

## Android V2 实装（当前 APK）

- **架构**：`web-prototype/` 是唯一 UI 源；Gradle 构建时复制到 `assets/web`，`MainActivity` 用全屏 WebView 加载。
- **原生桥**：`WebAppBridge` / `BiliApi` / `BiliExtras` / `CookieStore` / `StreamProxy` 提供热门、搜索、分集 cid、playurl、DASH、评论与楼中楼、弹幕、官方网页登录、Cookie、账户、收藏、历史、关注、动态、消息、排行榜、番剧/影视、直播、分区、视频详情、互动写入、会员中心、AI 接口、亮度、方向、剪贴板和截图。
- **真实数据**：首页推荐 / 热门 / 排行 / 番剧 / 影视 / 直播 / 分区 / 收藏 / 历史 / 关注；搜索；模块页；账户卡；动态 / 消息；视频信息；会员中心每日任务与经验记录。首页「推荐」直接请求 B 站首页推荐流 `index/top/feed/rcmd`，每次重新加载都会换一个 fresh 批次并去重，不再固定展示同一组热门视频。未登录的账户页会显示登录 CTA。
- **真实播放**：Bridge 取 B 站 progressive MP4；默认 720P，最高 1080P，画质台阶 120 / 116 / 112 / 80 / 74 / 64 / 32 / 16 逐级回退，切到实际可用画质时会在播放器内提示原因，并在画质面板里只显示当前视频实际支持的分辨率。DASH/MSE 只在用户选择 720P 以上画质时启用；`.m4s` 媒体代理使用桌面 UA 以通过 B 站 CDN 的 UA 校验。本地代理补齐 Referer/UA 并转发 Range；番剧按集播放并加入播放列表；直播 HLS 使用 hls.js；HTML5 `<video>` 播放。
- **真实登录**：登录页为无卡片、无说明文字的极简平面布局，只有「登录 B 站账号」标题和一个透明描边按钮「前往 B 站登录」；点击后在应用内打开 B 站官方登录页，手机号 / 密码 / 扫码等登录方式全部由官方页面处理，不再在 App 内输入手机号或验证码，也没有本地测试码；官方页登录成功后自动同步 `SESSDATA` / `bili_jct` 并进入首页。退出登录会同时清空原生 `CookieStore` 和 WebView Cookie，保证下次打开官方登录页时处于未登录状态。
- **系统亮度 / 音量**：播放器不再执行左右竖滑调亮度 / 音量；系统亮度、系统媒体音量完全交给设备和系统控制。App 不修改、不持久化、也不恢复亮度或音量，不修改 `<video>` 元素音量。
- **播放器**：播放/暂停、进度、倍速、循环、画质重取、三区手势、收起播放、全屏真实评论（三段窗口无限列表 + 楼中楼）、真实弹幕滚动、信息/性能面板、截图保存到相册、复制 BV 链接、收藏/投币/关注/点赞、弹幕发送、外接键盘映射、深色主题与外观滑杆、会员任务、AI 养鱼。评论发送入口暂时隐藏。播放使用系统硬解，默认 720P；不提供插帧、CAS、Anime4K 或逐帧后处理，避免持续 GPU 后处理和额外发热。界面层独立按屏幕刷新率运行，最高 120Hz。
- **加载状态**：所有需要网络等待的内容先绘制骨架屏再发起同步桥请求，避免真机上先卡住再突然出内容。覆盖首页 / 模块 / 搜索 / UP 主 / 收藏 / 历史 / 关注视频流、动态、消息、会员任务、账户卡、视频详情、评论、评论分页和播放器信息面板。骨架尺寸尽量沿用真实内容尺寸，图标、封面、头像先占位再淡入；分页加载只在底部显示一行尾部加载状态，不再插入局部骨架，不会整页闪烁。骨架颜色跟随主题，浅色为浅灰、深色为深蓝灰。
- **列表**：视频行左滑展开「播放列表 / UP主」动作，拖到按钮触发；浮动框加高并接近全宽、上滑展开播放器、点击进播放列表页；触底加载下一段真实数据；只保留最近两段，正在看的旧一段不会被提前卸载，等它完全滚出屏幕后再回收，并按当前可见行重新校准滚动位置，避免加载时跳页；历史行显示观看进度。
- **构建**：
  ```bash
  ./gradlew :app:assembleDebug
  adb install -r app/build/outputs/apk/debug/app-debug.apk
  ```
- **模拟器验证**：`Medium_Phone_API_37.0`，480×800 / 160dpi。已验证登录 gate / 官方登录入口、首页推荐 20 条（每次进入重新随机推荐批次）、搜索“原神”20 条、排行/番剧/影视/分区真实列表、番剧第一集 360P 播放（整季 11 集入队）、真实评论（8709 条）、最新评论未登录回退最热、楼中楼展开 12 条、触底无限加载、侧边栏、左滑播放列表、播放列表页/左滑删除、视频信息/性能面板、截图（MediaStore）、复制链接、画质切换、倍速/循环、我的页账户卡、视频流刷新率、五条播放 HUD、深色/浅色主题、DASH 720P 在线播放、WebGL 插帧/CAS。直播列表 20 条和直播地址 HLS 已验证；模拟器长时间 720P/直播软解会让模拟器不稳定，真机为准。
- **未验证 / 需要账号**：真实登录后的收藏/历史/关注/动态/消息/会员任务、4K/1080P+（需要大会员）、点赞/投币/收藏/关注/评论/弹幕发送、直播弹幕（B 站匿名接口 -352，需登录 Cookie）、AI 养鱼（需要用户提供 DeepSeek/OpenAI 兼容 Key）。这些入口在条件不满足时会内联提示，不会伪造成功。

## 移动端 V2 规划（当前）

- **不要底部工具栏**：视频流占满整个窗口；在屏幕上向右滑，从左边展开侧边栏。
- **强制登录**：未登录冷启动直接停在登录 gate，首页、侧边栏、搜索、播放器、播放列表全部不可达；登录页只有一个透明描边按钮「前往 B 站登录」，点击后打开 B 站官方登录页，登录成功后同步 Cookie，不再在 App 内输入手机号 / 验证码，也没有本地测试码；退出登录会同时清空原生 CookieStore 和 WebView Cookie，保证下次打开官方页时是未登录的干净状态；二维码登录代码和页面已全部删除，只保留官方网页登录。我的 → 账户可退出。
- 侧边栏列出了全部导航入口：首页 / 收藏 / 直播 / 番剧 / 动态 / 消息 / 历史 / 我的；不再有搜索按钮，「关注」不再出现在侧边栏。
- 侧边栏使用统一的极简线性 SVG 图标（无 emoji）；「我的」独立放在侧边栏底部，与主入口之间用分隔线隔开。
- 养鱼（AI 看片）入口默认隐藏；我的 → 防干扰 → 隐藏养鱼入口 可恢复。
- 首页/搜索/模块/UP 主视频流使用固定的 10 条一块滑窗：屏幕上最多只保留 3 块真实内容（30 行），另外最多缓存一页的下一页数据用于下一块；距离底部约 900px、且滚动完全停下后才请求下一页，分页加载只在底部显示一行加载状态，不再往列表里插入 20 条等高骨架。手指或惯性滚动期间不发起同步桥请求、不插入新块也不卸载旧块；提前返回的新数据先进入队列，等滚动停下约 0.22 秒后再渲染。之后以屏幕垂直中心所在的那一行作为当前焦点块：焦点进入第 3 块时，先在末尾渲染下一块，再把最旧的一块整块卸载，并清空该块的条目数组、DOM 节点和封面引用；卸载前记录当前屏幕最上方可见行及其位置，移除旧块后同步补偿滚动距离，所以正在看的第 23 条保持原位，向前看的第一条变成第 11 条，0-10 已从 DOM 和缓存中移除，不能再滚回去。DOM 行数、块数和预取数据因此始终有上限，不会随无限刷新增长。首屏仍先显示骨架，真实内容返回后原地替换；加载中以及刚加载完的短冷却时间内不会重复请求，到底后连续拖动不会一次加载多段；如果滚动或切页过快，某个加载结果已经变成旧块之后会取消这次加载，不再插入列表。
- 首页右滑打开左侧菜单；整块菜单从左向右滑入，不再是从左往右逐块显露。菜单最宽为屏幕的 1/2，所有菜单项内容左右居中。菜单项不是独立圆角卡片：左侧直接贴住屏幕 / 菜单左边缘，只有右侧是 18px 圆角，选中、悬停或拖动选中时呈现从左边长出来的书签式标签；底部「我的」同样贴左，分隔线向内缩进。菜单面板是半透明磨砂玻璃（backdrop blur + 内高光 + 右侧投影），能透出底层内容的模糊颜色。面板宽度与手指水平拖动 1:1 实时同步：拖多少开多少，松手后不到 22% 回弹关闭，超过 22% 补到全开。滑出后按住不动进入选择模式，菜单保持当前展开大小，不会强制全开；拇指上下移动的距离平均分给中间导航区的菜单项（不包含底部「我的」），从当前页面开始做相对移动，不再需要把手指滑到目标项的实际高度；每次切换距离比旧版更短，首尾循环选择。松手等同点击并关闭侧边栏进入对应页面。菜单打开后左滑菜单或遮罩也会跟手收起，剩余不足 78% 时关闭，否则回弹到全开。滑出时主页面以缩放/侧移向后退出：桌面保留轻微 3D 侧转，手机改用更轻的 2D 缩放和侧移，避免大面积 3D 变换导致掉帧；阴影与圆角随拖动进度同步，磨砂模糊降到 20px，侧边栏本身不再整体淡入而是纯滑动。松手后的自动展开 / 回弹与跟手拖动共用同一套逐帧变换（展开约 260ms、回弹约 220ms），不再触发会重算圆角和阴影的 CSS 过渡，因此快速右滑松手也能顺滑补完；从外部关闭仍保持 360ms 缓动。
- 所有页面都不设顶栏/标题栏：状态栏下只有玻璃渐变，内容直接开始；一行一个视频；整体行高加大。
- 视频流改为 YouTube 风格卡片：每张卡与屏幕等宽，上方是 16:9 视频预览，四周 12px 圆角，右下角显示时长，已看过的视频底部显示红色进度线；下方一行左侧是 38px 圆形 UP 头像，右侧是标题（最多两行、16px 粗体）、UP 名、播放量和带热度颜色的发布时间组件。卡片之间留 12px 间距，不再使用横向渐变或旧版左图右文布局；首页视频流最上方一条通栏发丝分割线，再开始第一张卡片，卡片之间不互加分割线。当前位于视口中心的卡片在滚动停稳后会直接在预览上静音播放视频，底部显示一条 4px 红色进度条，并保留静音标识；点击该卡片进入全屏时会从预览停止的时间点继续播放，进度百分比同步到底部播放列表；手指触摸、打开播放器 / 搜索 / 侧边栏或切换页面会立即停止预览。UP 主视频列表使用同一套卡片。

## 0. 播放管线（性能重构）

两端统一使用系统 WebView 媒体层硬解，V2 播放器只有一个 `<video>`，不再保留第二套 MediaCodec / VideoToolbox / Metal 测试播放器。

- **渐进优先**：默认 720P；480P / 720P 走 progressive MP4，不进入 MSE。1080P 及以上（1080P / 1080P+ / 4K）由 DASH 提供，只在用户主动选择时启用，避免默认播放进入 MSE 长时间缓冲和 seek；画质面板只列出当前视频实际存在的清晰度。
- **DASH 可选**：代码保留 DASH 拉流和 MSE 路径，`.m4s` 代理自动切换桌面 UA 以通过 CDN 校验；选择 720P 以上画质时使用，并注意缓冲配额与 seek 行为。
- **预览续播**：信息流中心 2/3 区域的视频获得预览播放权；滚动期间不切换、不暂停当前预览，滚动停止约 900ms 后才预载并切换新的中心视频。滚动时预览降到 0.5 倍速以降低软解码压力，停止后恢复 1 倍速；切换时旧预览保持播放直到新预览真正开始，避免空白和一播一停。
- **CDN 容错**：媒体代理的同一个本地播放地址同时携带主 CDN 和备用 CDN，主地址返回 403 / 404 时自动用备用地址重试同一段 Range，并记住失效地址，避免部分视频因主 CDN 拒绝而显示「播放失败」。
- **画质列表**：来自 progressive `accept_quality`，只显示当前视频实际可用的清晰度；切换画质保留当前播放进度，不会把列表缩回单一项。
- **不做逐帧后处理**：移除插帧、CAS、Anime4K、环境模糊画布和所有逐帧 canvas/WebGL 读回；视频区域使用纯黑背景，避免持续 GPU 模糊。界面调试信息保留：视频流右上角显示刷新率 / 帧率，播放器内显示画面 / 弹幕 / 界面帧率、分辨率、网络、缓冲和下集预载。
- **界面高刷**：视频解码维持独立，其他所有 UI 共用屏幕刷新率，最高 120Hz。Android 在当前分辨率下选择最高不超过 120Hz 的显示模式；iOS 关闭 WebKit 的 60fps 页面渲染限制并启用 ProMotion。侧边栏、搜索、页面切换、播放器控件、手势跟手和所有过渡动画都跟随该刷新率。
- **单一解码**：不再有自定义 MediaCodec / SurfaceTexture / Metal 测试管线，也不再打包 6MB 测试视频；解码完全交给系统硬解。
- **设置迁移**：旧版本保存的 1080P60 / 1080P+ / 4K 会自动回落到 720P，避免升级后继续默认高码率。

## 1.1 iOS 自动构建（unsigned）

`.github/workflows/ios-unsigned.yml` 在每次 push 时自动跑：

- `expo prebuild --platform ios`
- `pod install`（自动链接 `modules/o11a1-bridge`）
- 构建 **unsigned** `iphoneos` app，打成 `o11a1-ios-unsigned.ipa`
- 同时构建 `iphonesimulator` app，打成 `o11a1-ios-simulator.zip`

说明：

- unsigned IPA 不能直接安装到未越狱 iPhone；下载后自己用证书 / Sideloadly / AltStore 等方式签名安装。签名方案和免费 Apple ID 限制见 [SIGNING.md](SIGNING.md)。

- iOS 与 Android 共用同一套 WebView 播放器；默认 progressive，DASH 路径保留在 `DASH_PLAYBACK` 开关后，需要在支持 MSE 的 WKWebView 上单独启用和验证。
