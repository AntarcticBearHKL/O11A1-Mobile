# O11A1 移动端视频测试

![android-debug](https://github.com/AntarcticBearHKL/O11A1-Mobile/actions/workflows/android-debug.yml/badge.svg)
![ios-unsigned](https://github.com/AntarcticBearHKL/O11A1-Mobile/actions/workflows/ios-unsigned.yml/badge.svg)

仓库里有两套 V2 客户端：

- `expo-ui/`：iOS V2 客户端。Expo 壳 + 全屏 WKWebView + 本地回环 Bilibili 桥（`modules/o11a1-bridge`）；UI 仍然是 `web-prototype/`，播放走 HTML5 `<video>` + 本地 Range 代理。
- 根目录：Android V2 应用（`com.o11a1.videotest`）。全屏 WebView 承载 V2 设计 + 原生 Bilibili 桥 + 本地视频代理；旧 MediaCodec / GLES3 测试类保留在工程里。

## 只调 UI：Expo Go 模式

完整的 O11A1 app **不能直接**用 Expo Go 跑，因为 `expo-ui` 依赖自定义原生模块 `O11A1Bridge`（本地 HTTP 服务、Cookie、B 站接口、原生 WebView 宿主）。Expo Go 里没有这个模块，所以原来的行为是直接显示“原生模块未加载”。

现在 `App.tsx` 增加了 UI MOCK 回退：

- 在 Expo Go 中启动时检测不到 `O11A1Bridge`，会自动把 `web-prototype/` 的 `index.html / styles.css / app.js / native.js` 内联进一个 WebView。
- 注入 `window.O11A1Native` 的 mock 实现：热门/搜索/排行/番剧/直播/收藏/历史/关注/动态/消息/评论/楼中楼/会员任务都有假数据。
- 登录 gate、短信登录卡片、侧边栏、播放器设置抽屉、画质/插帧/增强/弹幕设置/循环模式/评论/播放列表/主题/外观滑杆/键盘映射等 UI 都可以点。
- 视频播放、真实账号、离线下载、AI、截图、复制链接会显示“UI 调试模式…”的内联提示，不会伪造成功。
- 左上角会显示 `UI MOCK · 无视频 / 无账号` 标识。

启动：

```bash
cd expo-ui
npm run dev
```

`npm run dev` 会同时启动 Expo 和 `web-prototype` 文件监听：改 `web-prototype/app.js / native.js / styles.css / index.html` 后自动重生成 `src/webapp.generated.ts`，Expo Go 会重新加载 WebView；改 `App.tsx` 则由 Metro Fast Refresh 处理。

快速在 Android 模拟器上自动打开 Expo Go：

```bash
npm run dev:android
```

iOS Simulator（macOS）：

```bash
npm run dev:ios
```

也可以分别启动：

```bash
npx expo start --lan
# 另一个终端
npm run watch:web
```

用 Expo Go 扫 Metro 的二维码，或在 Expo Go 里打开同一局域网地址。局域网不通时用：

```bash
npx expo start --tunnel
```

如果只想在电脑上快速看 UI，直接起一个静态服务器打开 `web-prototype/` 也可以；Expo Go 模式的好处是能在手机上测试触摸手势和横屏设置抽屉。

## iOS V2 实装（当前 IPA）

- **架构**：`expo-ui` 启动 `O11A1Bridge` 原生模块，在 `127.0.0.1` 随机端口起一个本地 HTTP 服务，把打包进 JS 的 `index.html / app.js / native.js / styles.css` 原样提供给 WKWebView。
- **同步桥**：注入 `window.O11A1Native`，通过同步 XHR 调本地 `/api/*`，与 Android 的 `WebAppBridge` API 完全一致；`native.js` 不需要分叉。
- **真实数据**：Swift `O11A1BiliClient` 直接请求 B 站热门、搜索、分页 cid、playurl、评论、弹幕、导航登录态、账户资料、收藏夹、历史、关注动态、动态、消息、排行榜、番剧/影视索引、番剧选集、直播推荐与直播地址、分区、视频详情；Cookie 持久化到 UserDefaults。
- **真实登录**：应用内打开 B 站官方短信验证码登录页；登录成功后读取 WebKit Cookie 并保存 `SESSDATA` 等 Cookie。
- **真实播放**：progressive MP4 优先 720P，失败回退 480P / 360P；本地 `/media` 代理补 Referer/UA、转发 Range，按 8MB 分块返回 206；主 CDN 失败自动试备用 CDN；番剧通过 `pgc/player/web/playurl` 播放并一次加入整季选集；直播使用原生 HLS；1080P / 4K / 1080P+ 会先尝试 DASH，失败自动回退渐进播放。
- **离线缓存**：`O11A1Downloads` 在 Documents/offline 保存 progressive MP4，支持进度、暂停、继续、断点续传、删除，完成后由本地 `/file` 路由播放。
- **播放器**：与 Android 共用同一套 V2 播放器 UI、三区手势、评论、弹幕、播放列表、刷新和登录 gate；视频信息/性能面板、截图、复制链接、收藏/投币/关注/弹幕发送会调用真实接口（未登录时内联提示）；外接键盘映射、深色主题、全屏评论楼中楼/三段窗口无限列表、会员任务、AI 养鱼、WebGL 插帧/CAS 全部共用 web 实现。
- **构建**：GitHub Actions `ios-unsigned`（macOS）每次 push 生成未签名 IPA + 模拟器 zip；成功后发布到 Releases。
- **下载**：
  - IPA：`https://github.com/AntarcticBearHKL/O11A1-Mobile/releases/download/ios-unsigned/o11a1-ios-unsigned.ipa`
  - 模拟器包：`https://github.com/AntarcticBearHKL/O11A1-Mobile/releases/download/ios-unsigned/o11a1-ios-simulator.zip`
  - Android APK：`https://github.com/AntarcticBearHKL/O11A1-Mobile/releases/download/android-debug/app-debug.apk`
- **安装**：未签名 IPA 需要自己签名（Sideloadly / AltStore / eSign / 自有开发者证书）；模拟器 zip 解压后用 `xcrun simctl install booted O11A1.app`，需要 macOS。
- **CI 验证**：`ios-unsigned` 在 macOS runner 上启动 iOS Simulator，已实际跑通登录 gate + 短信登录入口 → 本地测试进入 → 真实热门流 → 首个视频 720P 播放 + 弹幕。Release 里的 `ios-simulator.png` 是登录 gate，`ios-simulator-player.png` 是真实播放画面。真机仍需你自己签名后测试。
- **系统亮度 / 音量**：播放器不再监听左右竖滑，也不提供应用内亮度或音量滑杆；亮度和音量完全交给系统控制。进入、退出播放器都不会修改或恢复系统亮度，也不会修改 `<video>` 元素音量；外接键盘的音量快捷键也已移除。

## Android V2 实装（当前 APK）

- **架构**：`web-prototype/` 是唯一 UI 源；Gradle 构建时复制到 `assets/web`，`MainActivity` 用全屏 WebView 加载。
- **原生桥**：`WebAppBridge` / `BiliApi` / `BiliExtras` / `DownloadManager` / `CookieStore` / `StreamProxy` 提供热门、搜索、分集 cid、playurl、DASH、评论与楼中楼、弹幕、短信登录、Cookie、账户、收藏、历史、关注、动态、消息、排行榜、番剧/影视、直播、分区、视频详情、互动写入、会员中心、AI 接口、离线下载、亮度、方向、剪贴板和截图。
- **真实数据**：首页热门 / 排行 / 番剧 / 影视 / 直播 / 分区 / 收藏 / 历史 / 关注；搜索；模块页；账户卡；动态 / 消息；视频信息；会员中心每日任务与经验记录。未登录的账户页会显示登录 CTA。
- **真实播放**：Bridge 取 B 站 progressive MP4；1080P / 1080P60 / 1080P+ / 4K 先请求 DASH，用 MediaSource 分流视频/音频，失败自动回退渐进播放。画质回退会按 120 / 116 / 112 / 80 / 74 / 64 / 32 / 16 的完整阶梯逐级尝试，不再从 4K 直接掉到 720P；切到实际可用画质时会在播放器内提示原因，并在画质面板里显示当前视频实际支持的分辨率。本地代理补齐 Referer/UA 并转发 Range；番剧按集播放并加入播放列表；直播 HLS 使用 hls.js；HTML5 `<video>` 播放。
- **真实登录**：应用内打开 B 站官方手机号 + 短信验证码登录页；登录成功后读取 WebKit Cookies 保存 `SESSDATA` / `bili_jct`，不再提供二维码入口；「本地测试进入」仅用于无账号调试。
- **系统亮度 / 音量**：播放器不再执行左右竖滑调亮度 / 音量；系统亮度、系统媒体音量完全交给设备和系统控制。App 不修改、不持久化、也不恢复亮度或音量，不修改 `<video>` 元素音量。
- **播放器**：播放/暂停、进度、倍速、循环、画质重取、三区手势、收起进浮动播放列表、全屏真实评论（三段窗口无限列表 + 楼中楼）、真实弹幕滚动、信息/性能面板、截图保存到相册、复制 BV 链接、收藏/投币/关注/点赞、弹幕发送、外接键盘映射、深色主题与外观滑杆、会员任务、AI 养鱼、WebGL 插帧 / CAS / Anime4K。评论发送入口暂时隐藏。插帧 / 增强开启时会请求屏幕高刷新率；如果屏幕或 WebView 只能到 60Hz，会在播放器内提示实际上限，不把 60 帧伪装成 120 帧；WebGL 不可用时增强会降级为 CSS 滤镜并明确提示。
- **加载状态**：所有需要网络等待的内容先绘制骨架屏再发起同步桥请求，避免真机上先卡住再突然出内容。覆盖首页 / 模块 / 搜索 / UP 主 / 收藏 / 历史 / 关注视频流、动态、消息、会员任务、账户卡、视频详情、相关推荐、评论、评论分页和播放器信息面板。骨架尺寸尽量沿用真实内容尺寸，图标、封面、头像先占位再淡入；分页加载在底部插入局部骨架和尾部加载动画，不会整页闪烁。骨架颜色跟随主题，浅色为浅灰、深色为深蓝灰。
- **调试信息**：视频流右上角实时显示 FEED 刷新率与 FPS；播放器右下角、底部工具栏上方是与桌面客户端一致的 7 行视频调试 HUD，左对齐、固定 17px 行距，深色圆角面板配 1px 细边，内容依次为画面帧率（含毫秒）、弹幕帧率、界面帧率、分辨率（源 / 解 / 屏）、网络（实时读取 / 视频码率与倍率）、缓冲长度、下集预载。
- **离线缓存**：`DownloadManager` 支持两种任务：渐进 MP4 直接缓存；DASH 音视频分轨下载后用 `MediaMuxer` 交错合流成 MP4（FFmpeg 合流的原生等价实现）。支持队列、进度、暂停、继续、断点续传、删除和本地播放。
- **列表**：视频行左滑展开「播放列表 / UP主」动作，拖到按钮触发；浮动框加高并接近全宽、上滑展开播放器、点击进播放列表页；触底加载下一段真实数据；只保留最近两段，正在看的旧一段不会被提前卸载，等它完全滚出屏幕后再回收，并按当前可见行重新校准滚动位置，避免加载时跳页；历史行显示观看进度。
- **构建**：
  ```bash
  ./gradlew :app:assembleDebug
  adb install -r app/build/outputs/apk/debug/app-debug.apk
  ```
- **模拟器验证**：`Medium_Phone_API_37.0`，480×800 / 160dpi。已验证登录 gate / 短信登录入口、热门 20 条、搜索“原神”20 条、排行/番剧/影视/分区真实列表、番剧第一集 360P 播放（整季 11 集入队）、真实评论（8709 条）、最新评论未登录回退最热、楼中楼展开 12 条、触底无限加载、侧边栏、左滑播放列表、播放列表页/移除、视频信息/性能面板、截图（MediaStore）、复制链接、画质切换、倍速/循环、设置账户卡、视频流刷新率、五条播放 HUD、深色/浅色主题、渐进 MP4 离线下载 141.5MB、DASH 分轨下载 + MediaMuxer 合流 11.6MB（360P，音频解码计数 >0）并从本地播放、DASH 720P 在线播放、WebGL 插帧/CAS。直播列表 20 条和直播地址 HLS 已验证；模拟器长时间 720P/直播软解会让模拟器不稳定，真机为准。
- **未验证 / 需要账号**：真实登录后的收藏/历史/关注/动态/消息/会员任务、4K/1080P+（需要大会员）、点赞/投币/收藏/关注/评论/弹幕发送、直播弹幕（B 站匿名接口 -352，需登录 Cookie）、AI 养鱼（需要用户提供 DeepSeek/OpenAI 兼容 Key）。这些入口在条件不满足时会内联提示，不会伪造成功。

## 移动端 V2 规划（当前）

- **不要底部工具栏**：视频流占满整个窗口；在屏幕上向右滑，从左边展开侧边栏。
- **强制登录**：未登录冷启动直接停在登录 gate，首页、侧边栏、搜索、播放器、播放列表全部不可达；点「打开短信登录」/「本地测试进入」进首页，登录态本地保存；设置 → 账户可退出。
- 侧边栏列出了全部导航入口：首页 / 收藏 / 直播 / 关注 / 动态 / 消息 / 历史 / 我的；不再有搜索按钮。
- 侧边栏使用统一的极简线性 SVG 图标（无 emoji）；「我的」独立放在侧边栏底部，与主入口之间用分隔线隔开。
- 养鱼（AI 看片）入口默认隐藏；设置 → 防干扰 → 隐藏养鱼入口 可恢复。
- 首页/搜索/模块视频流使用提前预加载：距离底部约 900px 就开始加载下一段，不等真正触底。加载开始时会立即插入与下一段等高的加载骨架，真实内容返回后在原位置替换骨架，列表高度和滚动位置不跳；底部不再显示“正在加载 / 已经到底了”的文字行，只有加载失败时保留重试按钮。每次追加一段，只保留最近两段（1+2 → 2+3 → 3+4），旧段自动丢弃并保持滚动锚点；不再有下拉刷新。追加前先保存滚动位置，移除旧段后按保存值补偿；封面图淡入，避免加载新段时列表闪烁。加载中以及刚加载完的短冷却时间内不会重复请求，到底后连续拖动不会一次加载多段；如果滚动或切页过快，某个加载结果已经变成旧段之后，会取消这次加载并同时删除对应骨架，不再插入列表。
- 首页右滑打开左侧菜单；整块菜单从左向右滑入，不再是从左往右逐块显露。菜单最宽为屏幕的 1/2，所有菜单项内容左右居中。菜单项不是独立圆角卡片：左侧直接贴住屏幕 / 菜单左边缘，只有右侧是 18px 圆角，选中、悬停或拖动选中时呈现从左边长出来的书签式标签；底部「我的」同样贴左，分隔线向内缩进。菜单面板是半透明磨砂玻璃（backdrop blur + 内高光 + 右侧投影），能透出底层内容的模糊颜色。面板宽度与手指水平拖动 1:1 实时同步：拖多少开多少，松手后不到 22% 回弹关闭，超过 22% 补到全开。滑出后按住不动进入选择模式，菜单保持当前展开大小，不会强制全开；拇指上下移动的距离平均分给中间导航区的菜单项（不包含底部「我的」），从当前页面开始做相对移动，不再需要把手指滑到目标项的实际高度；每次切换距离比旧版更短，首尾循环选择。松手等同点击并关闭侧边栏进入对应页面。菜单打开后左滑菜单或遮罩也会跟手收起，剩余不足 78% 时关闭，否则回弹到全开。滑出时主页面以 3D 缩放/侧移向后退出，带阴影与遮罩。底部播放列表栏属于主界面本身，跟着主界面一起缩放、侧移和被遮罩压暗，不再单独下滑或淡出。
- 所有页面都不设顶栏/标题栏：状态栏下只有玻璃渐变，内容直接开始；一行一个视频；整体行高加大。
- 视频流每一行：页宽的圆角磨砂玻璃卡片，行与行之间留 10px 间距；卡片是半透明白色渐变叠加 26px backdrop blur，带白色细边、顶部高光和极轻投影，能透出并模糊底层壁纸的桃 / 蓝 / 薄荷色，深色主题自动换成深色玻璃。首页视频行尽可能向左右展开：页面左右只留 4px、卡片内部左右只留 8px，缩略图到屏幕边缘约 13px，其余信息量不变。左侧仍是 16:9 圆角缩略图，随屏宽缩放并带极细描边，右下角显示时长；右侧标题最多两行，下面一行是 UP 主名字、圆点分隔符和发布时间，信息量与之前一致。详情页相关推荐在详情磨砂页内保持扁平列表，不重复叠玻璃卡片。
- 首页浅色背景完全对齐桌面版：`#FAFAFC` 冷白底 + 桌面版五层柔和径向渐变（桃 / 蓝 / 薄荷 / 薰衣草 / 奶油），60px 模糊、无点阵；顶部玻璃、侧边栏、弹层、卡片同步改为冷白中性色，不再使用暖黄纸底。
- 默认锁定竖屏：Expo、Android、iOS 启动和退出播放器都回到 portrait，系统方向和底层 App 始终保持竖屏；主页不再提供横向布局，原来的「横屏主页」开关和持久化状态已删除，竖屏锁在 Expo 配置、Expo Go 运行锁和 Android Activity 三处同时强制。播放器中间上滑切换横竖屏的手势已移除。播放时监听 `deviceorientation` 方向传感器：手机转到接近横向（约 55°）后，只让播放器层在竖屏窗口内旋转 90° 铺满物理横屏，转回竖屏自动恢复；系统方向不会改变，App 本身仍然是竖屏。旋转过程不显示任何提示框、横屏徽标或 HUD，只保留画面本身的变化。传感器权限被拒绝或不可用时保持竖屏，不伪造横屏状态。横屏状态下下滑仍然是收起，播放器保持横向画面原地缩小并飞向竖屏底部的播放列表，不会执行普通的向下平移。
- 搜索入口是常驻底部播放列表栏右侧的放大镜：点击后搜索抽屉以底栏当前高度为起点平滑长高到全屏，高度、顶部圆角、头部和内容一起过渡，不再瞬间跳到全屏或整块预先滑入；输入框自动获得焦点。没有输入时显示热门搜索，输入后显示联想词，点选或回车进入搜索结果。键盘弹出时抽屉保持全屏铺满，搜索内容底部按键盘高度增加滚动留白，键盘直接覆盖在抽屉玻璃上，不再在键盘周围露出白色 / 纸色边框；Expo 根视图、WebView 和 Android 窗口背景统一为 `#FAFAFC`。Android 原生 Activity 使用 resize 模式，Expo Go / WebView 再用 visualViewport 兜底。搜索结果是从右侧滑入的独立页面，顶部标题栏贴住页面最顶端，标题左对齐，不再显示返回三角和右侧「搜索结果」文字；右滑时页面跟手向右移动，松手后继续完整滑出屏幕并露出进入搜索前的页面，再卸载这一层。UP 主主页使用同一套覆盖层手势，右滑关闭时也是整页滑出而不是瞬间切换。原来的首页上滑浮动搜索框和显示/隐藏逻辑已移除。
- 播放列表不在侧边栏：底部改为常驻的全宽贴底栏，不再是浮动卡片；高 88px + 安全区，顶部 24px 圆角，底边贴住屏幕，从最底部一直延伸到左右两边。整条栏是半透明磨砂玻璃（backdrop blur + 柔和的向上投影），没有上边框白线或内高光。收起时栏内不再显示封面，而是居中显示当前播放状态（正在播放 / 已暂停 / 待播放）、一行视频标题和一行 UP 主名，右侧保留搜索图标按钮；没有播放内容时显示「暂无播放内容 / 左滑视频加入」。上滑时不是整条栏向上平移：底边保持不动，栏体高度随手指向上拉伸，顶部圆角和投影同步增强；滑过阈值后抽屉停在约 55% 屏高，展开当前播放列表，不进入全屏页面，向下拖可以收回。展开后不再显示拖拽把手，顶部改成一行三栏：左侧无背景的播放模式按钮（循环 / 继续 / 下一分P / 暂停顺序切换）、中间居中的「播放列表」标题、右侧「清空列表」按钮，三者垂直中线对齐；清空需要连续点两次确认，搜索按钮只在收起时显示。列表为空时，展开区域只显示居中的「播放列表是空的」，不显示额外加入提示，文字在列表区域上下左右居中。收起与展开时，居中的播放信息向上淡出、模式 / 标题 / 清空工具栏向下淡入，列表随抽屉高度和淡入动画进入，反向操作同样平滑。点击收起状态的播放列表栏时，黑色播放器窗口直接从底栏当前矩形（顶部圆角、下边贴底）向上展开到全屏，底栏保持原位被窗口覆盖，展开完成后再淡出隐藏；展开状态点击列表项时从该项缩略图展开，点击顶部工具栏不会误触播放器。播放列表为空时点击收起状态的底栏会展开空抽屉。完整播放列表页仍可从播放器里的列表按钮进入。
- 视频行左滑不会移动整行：整行覆盖一层随手指逐渐加深的遮罩，右侧实时显示将要执行的动作，行本身保持原位。左滑第 24px 先解锁「加入播放列表」，松手立即加入；继续滑到 160px 切换为紫色「查看 UP 主」，松手打开该视频的 UP 主主页。遮罩颜色随动作从蓝变紫，未达到当前阶段阈值时松手自动消失。加入播放列表时，松手后遮罩直接渐变消失，不再整行压暗或闪白，只保留缩略图飞入播放列表的动画。
- UP 主主页是固定在播放器之上的右侧滑入页：顶部不再有 UP 信息栏，视频列表从安全区下直接开始。页面分成独立滚动的视频区和固定在屏幕底部的信息栏：底部第一行是两个居中的胶囊按钮「最新发布 / 播放量」，没有外层容器背景和「共 N 个投稿」数量，选中按钮使用墨色实心、未选中使用表面色；紧挨着下面一行是稍微加高的 UP 信息区，显示 40px 头像 / UP 名字 / UID / 粉丝数和关注按钮，UP 主标题固定在屏幕最底下。视频列表直接读取 UP 主空间投稿接口，切换排序时列表回到顶部、显示骨架屏再重新请求；列表支持触底加载。底部选择器和标题栏不随列表滚动，不会跟着列表一起上下移动。打开时从右侧完整滑入；在 UP 页右滑会把整层跟手向右推并退出，露出播放器/原来的页面，这个右滑不会触发左侧边栏。从视频详情点作者会先让详情向左滑出、UP 页同时从右侧滑入；在视频行继续左滑到第二阶段「查看 UP 主」也会打开 UP 页。退出后原来的滚动位置保持；UP 页内部仍然支持行左滑加入播放列表 / 查看 UP 主和触底加载。
- 全局禁用文字选中、长按呼出系统菜单和文字 / 图片拖拽，包含搜索输入框在内的所有元素都设置为不可选中；输入框仍然可以聚焦和正常输入，但不提供文字选择、复制或长按菜单。避免长按、拖动、左滑等手势被系统文字选择或菜单打断。
- 播放列表页支持全页下滑关闭：列表在顶部时从页面任意位置下滑，或从顶部抓手 / 标题区下滑；拖动时页面跟手位移、缩放和淡出，松手后弹簧回弹或关闭。播放列表页改为极简扁平样式：顶部只保留返回、标题和数量，视频行没有白色卡片、圆角容器、边框和序号，行与行之间只用一条细分隔线；每行是缩略图 + 单行标题 + UP / 时长 + 右侧移除按钮，当前项只用蓝色标题区分。底部展开的播放列表也使用同一套扁平行样式，并移除了重复的列表小标题。
- 播放器播放时保持全屏。从视频流点击条目打开播放器时，黑色播放器窗口本身从该行缩略图的位置连续展开到全屏，展开过程中只显示纯黑窗口背景，不出现封面预览图、视频画面或控件；到达全屏后再淡入播放器内容。展开动画点击后立即开始，不再先等待同步播放请求；媒体请求延迟到展开和内容淡入之后（约 620ms），加载期间显示主题纸张底、旋转加载环和「正在打开视频…」，播放控件暂时隐藏，视频就绪后淡出加载层并恢复控件。视频详情预取继续顺延到媒体请求返回之后，避免同步桥抢占主线程；同一视频已经就绪时直接恢复，不显示加载环。垂直手势不再区分左 / 中 / 右三列：在画面左、中、右任意位置向下滑都会跟手收起播放器，向上滑都会打开设置抽屉；水平手势仍然分方向，左滑打开全屏评论，右滑从左侧滑入视频详情。单击画面任意位置都会显示底部浮动进度条。播放器收起时不再整体淡出：播放器随手指下移并在拖动过程中逐渐增加圆角（最多 28px）；松手后从当前已经拉下的位置直接继续缩小，不会再回到全屏，圆角继续过渡并按比例缩成圆角小窗，飞向底部播放列表的封面槽；落到目标后播放列表做一次轻微回弹/封面光晕，再显示底部栏。重新打开播放器会取消尚未完成的收起动画。亮度和音量交给系统控制，播放器不提供左右竖滑调亮度 / 音量；双击中间切换播放 / 暂停，暂停时不再显示红色边框，而是从视频边缘向中心渐入内阴影和暗角，整体亮度缓慢压低约 0.9 秒，中心保持可看；恢复播放时约 0.42 秒渐亮回原亮度。设置抽屉、评论或详情面板打开时只保留各自的后退压暗，不再叠加暂停边框；收起进播放列表的动画也不再带红框；长按左 0.5× 减速、长按右 2.0× 加速。
- 视频详情页：圆角磨砂玻璃全屏覆盖层，从左侧跟手滑入。顶部展示封面、标题、发布时间 / BV、UP 主入口、播放/弹幕/点赞/收藏数据和简介；右上角没有关闭按钮，在详情页任意位置向左滑（包括推荐视频行和页面上的按钮）都会让整页跟手向左滑出回到视频；滑动结束后会短暂抑制点击，避免误加入播放列表或误开 UP 主页。相关推荐改为和首页统一的视频流布局：同样的 112px 行高、10px 行间距、18px 圆角、16:9 缩略图和标题 / UP / 时间信息，左右只留 4px；不再使用扁平无间距列表。详情内视频行不再触发列表里的左滑动作，点击任意推荐行会直接加入播放列表，当前正在播放的视频不切换，标题右侧显示「点击加入」；如果该视频已在队列中则不会重复添加，也不会切到它。UP 主入口仍是扁平整行按钮，不做凸起卡片。相关推荐尽可能展示接口能返回的全部视频（请求 50 条，返回多少显示多少），不再是固定 6 条。底部不出现播放列表胶囊或播放列表栏；从详情进入 UP 页时详情向左关闭、UP 页同时从右侧进入。打开播放器后会在后台预取当前视频详情和相关推荐；详情按视频缓存，同一视频再次右滑直接复用已渲染内容，不重新请求也不闪骨架，切换视频时才使用对应缓存或加载。
- 亮度 / 音量不再由播放器管理：进入、退出播放器、切后台都不会读取、修改或恢复系统亮度或音量；用户直接用系统亮度和实体音量键调节。
- 播放器顶部菜单栏整条移除：不再有返回 / 标题 / 队列 / 更多按钮，也不保留任何顶部功能。底部只保留一条浮动的扁平移动标尺工具栏：左右各留 16px、底部留 14px + 安全区，圆角玻璃卡片，不再贴住屏幕底边；高度约 104px（小屏约 98px）。工具栏顶部不再显示毫秒级时间或总时长，改为一条 36 格的热力图式进度条：已播放的格子按离播放头的距离从蓝、青、黄、橙过渡到红色，播放头附近的格子最热，未播放格子保持灰色；进度条本身支持点击和拖拽，按下即预览对应位置，水平拖动与整条进度条 1:1 对应，松手才真正跳转。向上把手指拖离进度条后会进入精细调整：离进度条越远，同样的横向距离对应的进度变化越小，超过 6px 后每向上 80px 灵敏度减半，回到进度条附近又恢复 1:1。热力图下方是占满剩余高度的扁平滚轮：刻度随时间滚动，步长按屏宽自适应为 1 / 2 / 5 / 10 / 15 / 30 / 60 秒，每 5 格一根蓝色主刻度并带绝对时间标签，已播放刻度为蓝色、未来刻度为灰色；所有时间标签始终显示，指针压到标签上也不会消失。中心固定一条红色瞄准针和蓝色基准窗，二者的高度严格等于滚轮高度，不会上下冒出一截。滚轮支持点击和拖拽，向左拖动为前进，拖动时刻度连续跟随手指、只预览时间，松手才真正跳转；滚轮拖动时上方的热力图进度也同步预览。横屏时热力图和标尺跟着播放器旋转层一起旋转，拖动按旋转后的局部坐标换算，向上抬起手指的精细调整方向也与画面一致。不包含 A/B 循环或任何 A/B 播放功能，也没有静音、音量、弹幕输入框或播放 / 上下首按钮。
- 评论页：播放器左滑进入全屏磨砂玻璃圆角页，无顶部标题栏 / 关闭按钮，底部悬浮「最新 / 最热」两个 Tab 切换排序；右滑关闭，关闭再打开同一视频保持原滚动位置。评论加载和视频流一致：首次进入先显示骨架屏，数据回来原地替换；触底前预取下一页并在底部插入局部骨架，不裁剪旧评论、不做反向加载，也不会因为追加或调整分块而跳动。打开播放器后会后台预取当前视频首屏评论，评论按视频和排序缓存已经加载的页；再次滑入时直接渲染缓存，不再显示骨架或重复请求，切换视频时才使用该视频缓存或加载首屏。

- 播放器横竖屏共用：所有设置收进一个从底部上滑的磨砂玻璃抽屉。抽屉是与全局一致的半透明玻璃：38px 模糊、饱和度增强、顶部高光和细边，能透出后方视频的颜色。在画面左 / 中 / 右任意区域向上滑都能打开，打开后从屏幕任意位置向下滑都能跟手收起，点击抽屉外的遮罩不会关闭；从抽屉内容上开始下滑同样只收起抽屉，不会误触按钮。抽屉打开时暂停自动隐藏、隐藏底部进度条，向下拖动抽屉会跟手位移，松手超过阈值即收起。抽屉顶部不再有拖拽把手，改成一个居中的「设置」标题栏，只显示这两个字，没有副标题、UP 信息或操作提示。标题栏下方是扁平的单列设置列表：画质 / 插帧 / 增强 / 弹幕设置 / 循环模式，每项占一整行，用细分隔线分隔，没有背景框、圆角卡片或按钮底色，当前值显示在右侧。点击画质 / 插帧 / 增强 / 弹幕设置会直接在当前抽屉内向下展开对应选项或控制项，不再弹出第二个抽屉；同一时间只展开一项，再点一次收起，展开的选项同样保持无背景的扁平样式，弹幕的显示区域选项改为纯文字加蓝色选中态，循环模式点击循环切换。抽屉位于播放器旋转层内部，陀螺仪自动横屏时和画面一起旋转，横屏下不额外加顶部或底部栏；画质 / 插帧 / 增强 / 弹幕的展开内容也留在同一个旋转层里，方向和画面保持一致。
- 播放器底部标尺工具栏、上滑设置抽屉和播放器内提示都跟随界面主题：浅色主题使用浅色磨砂玻璃、白色刻度带和深色文字，深色主题使用深色玻璃与白字；主题切换即时生效，画质 / 插帧 / 增强 / 弹幕的内联选项沿用同一套主题变量。浅色主题下左右滑出的评论、视频详情和 UP 主页也改为近白纸张背景，只保留轻微磨砂和高光，不再透出黑色视频而发灰。视频比例与屏幕不一致时，画面后方会同步播放同一个视频的低分辨率镜像画布，按 cover 放大铺满并做 30px 高斯模糊和轻微放大，形成磨砂玻璃背景；前后画面同步播放，比例一致时自动关闭。没有画面或比例一致时，留白仍保持主题纸张色；WebGL 插帧 / 增强使用的后处理画布在氛围背景开启时使用透明底色。播放器从视频行展开时的黑色窗口动画保持不变。

## 0. 测试视频

两个平台统一使用 B 站 **BV1NS4t6oEXQ**（影视飓风 MacBook Pro PROLED XDR）的 30 秒测试片段：

- 1920×1080、H.264、29.97 fps、无音轨、约 6 MB
- Android：`app/src/main/assets/BV1NS4t6oEXQ.mp4`
- iOS：`expo-ui/modules/o11a1-video/ios/Resources/BV1NS4t6oEXQ.mp4`
- 未登录的 B 站接口最高只能取到 720P；1080P / 4K / 60fps 需要登录和大会员，客户端已经实现 DASH 请求与 MediaSource 播放，未登录时会自动回退到服务端允许的清晰度。

## 1. Expo 应用 / iOS 原生播放器

```bash
cd expo-ui
npm install
npx expo start
```

Expo Go 扫码只能看 UI。真正的播放器在 iOS 原生构建里：

- `VTDecompressionSession` 硬解优先（H.264 / HEVC，失败才回退软解）
- `AVAssetReader` 提供压缩样本，VideoToolbox 输出 BGRA
- Metal 采样上一帧/当前帧做 blend 插帧（60 / 120 目标）
- 同一个 fragment shader 里做 CAS-like 自适应锐化
- HUD 和解码统计：`H.264 HW`、分辨率、显示 Hz、render/decode fps、队列深度

原生视图由 `expo-ui/modules/o11a1-video` 提供，JS 只负责挂载和切换开关。

## 1.1 iOS 自动构建（unsigned）

`.github/workflows/ios-unsigned.yml` 在每次 push 时自动跑：

- `expo prebuild --platform ios`
- `pod install`（自动链接 `modules/o11a1-video`）
- 构建 **unsigned** `iphoneos` app，打成 `o11a1-ios-unsigned.ipa`
- 同时构建 `iphonesimulator` app，打成 `o11a1-ios-simulator.zip`

说明：

- unsigned IPA 不能直接安装到未越狱 iPhone；下载后自己用证书 / Sideloadly / AltStore 等方式签名安装。签名方案和免费 Apple ID 限制见 [SIGNING.md](SIGNING.md)。
- simulator zip 只能在 Mac 的 Simulator 里运行；Windows 不能跑 iOS Simulator。
- 当前未接音频、Anime4K 和 B 站 DASH 登录；DASH 播放只在 Android WebView 可用，iOS 自动回退渐进播放。

## 2. Android 原生测试

要求：

- Android Studio / Android SDK 35
- JDK 17
- 一台 Android 8.0+ 真机（必须；模拟器只能看管线通不通）

用 Android Studio 打开 `D:\Dev\o11a1-mobile-test`，等 Gradle 同步后运行 `app`。

或者在装有 SDK 的机器上：

```bash
./gradlew :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

也可以直接跑仓库里的 `android-debug` workflow（每次 push 自动构建），从 Actions artifact 下载 `app-debug.apk`；debug APK 已自动签名，直接安装。

启动后：

- 视频自动循环播放内置的 `BV1NS4t6oEXQ.mp4`（1920×1080、29.97fps、H.264、30 秒）。
- 左上角显示实际使用的解码器、`HW`/`SW`、分辨率、显示刷新率、渲染 fps、已解码帧数、插帧和 CAS 状态。
- 底部两个开关：
  - `插帧 blend`：用上一帧和当前帧做混合，验证双帧纹理 + 显示循环；这不是 MEMC，快速运动会有重影。
  - `CAS 锐化`：一个单 pass 的自适应锐化 shader（CAS-like，不是 AMD CAS 的逐像素完整实现），用来验证 GPU 后处理链路。
- `解码器探测`：列出 `MediaCodecList` 中 H.264 / HEVC / AV1 / VP9 解码器、HW/SW、支持分辨率和帧率。

日志与错误：

```bash
adb logcat -s O11A1VideoTest
```

### 怎么判断结果

- 左上角 `HW` 且解码器名是 `c2.qti.*` / `c2.mtk.*` / `OMX.qcom.*` / `OMX.Exynos.*` 一类，才说明走的是厂商硬解。
- `SW` 或 `c2.android.*` / `OMX.google.*` 说明是软件解码，不能用来评估手机硬解性能。
- 模拟器通常显示软件 codec；它只能验证 shader 编译、画面方向、回调和 UI，不代表真机帧率。
- 真机测试时重点看：1080p 是否能稳定、开插帧后 fps、开 CAS 后 fps、连续 5–10 分钟是否降频。

## 3. 现在测到什么、没测到什么

已覆盖：

- Android V2：WebView UI + 真实热门/搜索/模块数据、B 站短信验证码登录、progressive 720P 播放、评论、弹幕、播放列表、触底无限加载。
- Android 旧测试管线：MediaCodec 硬解、SurfaceTexture 零拷贝、GLES3 双帧 blend、CAS-like。
- iOS V2：Expo + WKWebView + 本地回环桥；CI 的 iOS Simulator 已跑通登录 gate/短信登录入口、真实热门流、首个视频 720P 播放、真实弹幕，截图随 Release 发布。
- iOS 旧测试管线：VideoToolbox 硬解、Metal 双帧 blend、CAS-like、60/120 目标、运行统计。
- 两端统一使用 BV1NS4t6oEXQ 测试片段。
- GitHub Actions 每次 push 自动构建 Android APK 和 unsigned iOS 包，并把 IPA/APK 发布到 Releases。

还没覆盖：

- DASH 分轨 / 4K / 60fps / 1080P+（需要大会员 Cookie 和 DASH 合流）。
- Anime4K Restore-CNN-S（多 pass，下一步单独压测）。
- 动态 / 消息 / 收藏 / 历史等账户页仍是设计壳；直播 / PGC 没有接独立接口。
- 插帧 / CAS / 增强 / 截图在 Android WebView 侧：插帧与增强走 WebGL 后处理（帧混合 + 锐化/饱和度），截图走原生 PixelCopy；120 帧输出需要屏幕与 WebView 都支持高刷新率，App 会请求高刷并在达不到时内联提示，不会伪造帧率。
- Android 端的 Expo 本地模块（当前仍是独立原生工程）。
- iOS 签名 / TestFlight。
